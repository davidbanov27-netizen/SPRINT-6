# Как работим в екип

## Клонове (branches)

| Клон | За какво е |
|------|------------|
| `main` | Стабилната версия. Винаги се компилира и стартира. |
| `feature/<име>` | Нова функция, напр. `feature/loan-extend` |
| `fix/<име>` | Поправка на грешка, напр. `fix/overdue-days` |
| `docs/<име>` | Само документи |

Работата започва така:

```bash
git switch main
git pull
git switch -c feature/loan-extend
```

## Съобщения за commit

Формат: `тип: кратко описание` (до около 70 знака, глагол в сегашно време).

| Тип | Кога |
|-----|------|
| `feat` | нова функция |
| `fix` | поправка на грешка |
| `docs` | документи |
| `refactor` | преструктуриране без промяна на поведението |
| `test` | тестове |
| `chore` | настройки, `.gitignore`, други дребни неща |

Примери: `feat: добавя удължаване на срока`, `fix: коригира броя дни просрочие`.

Един commit = една смислена промяна. Не смесвайте поправка и нова функция в един commit.

## Pull request

1. Качете клона: `git push -u origin feature/loan-extend`.
2. Отворете pull request към `main` (шаблонът се попълва автоматично).
3. Поне още един човек го преглежда. Ако сте сами, прегледайте го сами на следващия ден.
4. Сливане (merge) само след като проектът се компилира и работи.

## Задача е готова, когато

- [ ] проектът се компилира без грешки;
- [ ] функцията работи в приложението (проверена на ръка);
- [ ] бизнес правилата, които е засегнала, са покрити с тест (щом има тестове);
- [ ] статусът в `docs/backlog.md` е обновен;
- [ ] няма забравени `TODO`, дебъг редове и ненужни файлове.

## Правила за кода

- **Бизнес правило** = само в `LibraryService`. Не в `ViewModel` и не в XAML.
- **Нов екран** = `XxxView.xaml` + `XxxViewModel.cs` + `DataTemplate` в `MainWindow.xaml` + ред в `MainViewModel.Create`.
- Не добавяйте NuGet пакети без причина. Ако е нужно, запишете защо в описанието на pull request.
- Не качвайте `bin/`, `obj/`, `.vs/` и файлове с данни (`library.json`). Те са в `.gitignore`.
